# Backend

Серверная часть менеджера задач на Java 21 и Spring Boot

## Локальный запуск

### PostgreSQL

Для локальной разработки используются следующие значения

| Параметр | Значение |
| --- | --- |
| База данных | `task_manager` |
| Пользователь | `task_manager` |
| Пароль | `task_manager` |
| Порт | `5432` |

Это известные тестовые значения только для локальной разработки

### Приложение

Команда запускает в фоновом режиме все сервисы из `docker-compose.yml`

```bash
docker compose up -d
```

Liquibase автоматически применит миграции при запуске Spring Boot

```bash
mvn spring-boot:run
```

Пока Maven Wrapper неполный, поэтому для запуска нужен установленный Maven
После восстановления Wrapper можно использовать `./mvnw spring-boot:run`

## Импорт задач

`POST /tasks/import` принимает multipart-поле `file` с расширением `.json` или `.csv`.
Нужна активная сессия пользователя. Успех — `201 Created` без тела ответа.

JSON содержит непустой массив:

```json
[
  {"name": "Подготовить отчёт", "description": null, "priority": 3, "deadline": "2026-11-15T18:00:00+03:00"},
  {"name": "Проверить презентацию", "priority": 2, "deadline": null}
]
```

CSV в UTF-8 содержит заголовки (разделитель — запятая):

```csv
name,description,priority,deadline
Подготовить отчёт,,3,2026-11-15T18:00:00+03:00
Проверить презентацию,,2,
```

В CSV поддерживаются поля в двойных кавычках, запятые и переносы строк внутри них.
Приоритет — целое число от 0 до 10, как при обычном создании задачи.
Пустые необязательные поля CSV преобразуются в `null`; описание сохраняется как пустая строка.
Все задачи получают статус `planned`; текущий пользователь становится автором и владельцем.

Сохранение начинается только после успешного чтения и проверки файла.
Ошибки аннотаций собираются в одну строку `message` ответа `400` с кодом `IMPORT_VALIDATION_ERROR`.
Сообщение содержит поле и индекс JSON с нуля (`JSON[1]`) или физическую строку начала записи CSV
с единицы (`CSV, строка 3`). Ограничения полей проверяются теми же аннотациями, что и при создании задачи.
JSON преобразуется в DTO библиотекой Jackson; поля CSV преобразуются явно.
После чтения все задачи проверяются через аннотации DTO.
Ошибка формата числа, даты или структуры файла останавливает чтение сразу.
Для ошибок чтения JSON возвращается общее сообщение с ожидаемым форматом полей.
При любой ошибке ни одна задача не сохраняется. Повреждённый синтаксис JSON/CSV отклоняется сразу.

Сохранение выполняется одной транзакцией: ошибка БД также отменяет импорт целиком.
Для непустого файла выполняются два SQL-запроса: массовая вставка задач с возвратом ID,
затем массовая вставка владельцев в `task_members`.
Повторная успешная загрузка того же файла создаёт новые задачи.

Пример загрузки с cookie, полученной при входе:

```bash
curl -i -b cookies.txt -F 'file=@tasks.csv' http://localhost:8080/tasks/import
```
